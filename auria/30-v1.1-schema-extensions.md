# 30 — v1.1 Schema Extensions

Two schema extensions discovered while authoring the expanded v1 disorder template set (`22`–`29`). Both extend the existing schema (`01-schema-v3.md`, `02-cell-registry-spec.md`, `15-schema-extensions.md`) backward-compatibly. Existing templates and patient data remain valid without migration.

Read this alongside `15-schema-extensions.md`. Where 15 introduced predicted/observed deltas, FHIR mappings, and full-body extensibility, 30 introduces vocabulary expansion (sleep/circadian) and the subtype_overrides pattern for disorders with structurally distinct presentations.

---

## Extension A — Sleep / circadian vocabulary

**Why this exists.** The insomnia template (`28-insomnia-template.md`) and the sleep-relevant cells across MDD, anxiety, and PTSD cannot render correctly within the v1 region/system vocabulary. The circadian system has no representation. Sleep-relevant neuropeptide systems (orexin, melatonin) have no representation. Until these are added, sleep cells must be encoded as vegetative proxies, which loses mechanism resolution and prevents accurate drug coverage authoring (DORAs, melatonin receptor agonists, orexin antagonists all become invisible).

**Scope.** Add four regions, two systems, and one measure type to the v1 vocabulary. Mechanical schema change. No data migration required for existing disorder templates.

### New regions

Add to `registry.regions`:

| ID | Name | Anatomical scope | Primary relevance |
|----|------|------------------|-------------------|
| `SCN` | Suprachiasmatic Nucleus | Master circadian pacemaker (hypothalamus) | Circadian phase, light entrainment |
| `Hypo` | Hypothalamus | Hypothalamus (excluding SCN, treated as parent region) | HPA axis output, autonomic, neuroendocrine |
| `LH` | Lateral Hypothalamus | Lateral hypothalamic area | Orexin neurons, arousal, feeding-reward integration |
| `Pineal` | Pineal Gland | Pineal | Melatonin synthesis/release |

Region hierarchy note: `SCN` and `LH` are sub-regions of `Hypo`. The schema's existing region hierarchy field handles this; aggregations roll up correctly without code changes.

### New systems

Add to `registry.systems`:

| ID | Name | Class | Primary measurements |
|----|------|-------|----------------------|
| `Orx` | Orexin / Hypocretin | Neuropeptide | OX1R, OX2R receptor density; orexin neuron firing rate; CSF orexin-A concentration |
| `Mel` | Melatonin | Neuroendocrine | MT1, MT2 receptor density; DLMO timing; plasma melatonin amplitude |

### New measure type

Add to the cell `measure_type` enum:

- `circadian_phase` — encodes timing relative to a circadian zeitgeber (typically DLMO or core body temperature minimum). Delta values represent hours of phase shift relative to healthy baseline. Allowed range: −12 to +12.

### Effect on existing cells

None. All existing cells in templates `22`–`29` (except `28-insomnia-template.md`) and the OCD reference remain valid. The insomnia template's circadian subsystem can promote its proxy cells to native cells in a v1.1.0 minor revision.

### Effect on drug coverage authoring

Three drug classes become authorable that previously could not:

- **DORAs (dual orexin receptor antagonists)** — suvorexant, lemborexant, daridorexant. Coverage cells target `LH` × `Orx` × `OX1R/OX2R`.
- **Melatonin receptor agonists** — ramelteon, tasimelteon, agomelatine. Coverage cells target `Pineal` × `Mel` × `MT1/MT2`.
- **Z-drugs and benzodiazepine GABA-A modulators on sleep-onset cells** — already partially authorable in v1; the new vocabulary lets sleep-onset cells distinguish hypothalamic from cortical GABA-A.

## Extension B — Subtype overrides pattern

**Why this exists.** Some disorders have structurally distinct presentations whose cell-level neurobiology partially diverges from the canonical template. The PTSD dissociative subtype is the v1 motivating case: it shares ~75% of cells with the hyperarousal presentation but flips ~13 cells (amygdala, mPFC, rACC, insula) in direction. Splitting into two separate disorder templates duplicates the shared 75% and creates maintenance burden. Encoding subtype divergence as cell-level overrides is cleaner and clinically more honest — patients move between subtypes; the schema should reflect that.

**Scope.** Add three optional fields to existing types. Backward-compatible: templates and patients without subtype usage are unaffected.

### Schema additions

**DisorderTemplate gains `subtype_branches`:**

```typescript
type DisorderTemplate = {
  // ... existing fields ...
  subtype_branches?: SubtypeBranch[];
};

type SubtypeBranch = {
  id: string;                    // e.g., "dissociative", "hyperarousal", "melancholic", "atypical"
  name: string;                  // patient-facing label, e.g., "Dissociative subtype"
  description: string;           // clinician-facing one-paragraph description
  exclusive: boolean;            // if true, only one branch can be active per patient; if false, branches can combine
  selection_basis: "instrument" | "clinician" | "computed";  // how the subtype is determined
  selection_evidence?: string;   // free-text description of how to determine the subtype
};
```

**Cell gains `subtype_overrides`:**

```typescript
type Cell = {
  // ... existing fields ...
  subtype_overrides?: SubtypeOverride[];
};

type SubtypeOverride = {
  subtype_id: string;            // matches a SubtypeBranch.id from the cell's disorder template
  delta?: number;                // overrides base delta when the subtype is active
  delta_range?: [number, number]; // overrides base range
  confidence?: number;           // overrides base confidence
  sources: Source[];             // evidence for the override (REQUIRED — overrides cannot be evidence-free)
};
```

**PatientProfile gains `disorder_subtype_assignments`:**

```typescript
type PatientProfile = {
  // ... existing fields ...
  disorder_subtype_assignments?: DisorderSubtypeAssignment[];
};

type DisorderSubtypeAssignment = {
  template_ref: string;          // disorder template ID
  subtype_id: string;            // matches a SubtypeBranch.id in that template
  assigned_at: ISO8601;
  assigned_by: ClinicianRef;     // subtype assignment is always clinician-committed
  evidence?: string;             // free-text justification
};
```

### Effective-state computation change

The effective-delta formula gains one step. For each cell C in a disorder template T:

```
effective_template_contribution(C) =
  if patient has a DisorderSubtypeAssignment for T AND
     C.subtype_overrides contains an entry for that subtype:
    use the override's delta (and confidence)
  else:
    use C's base delta (and confidence)
```

The rest of the formula (baseline + Σ template_refs × severity + Σ subsystem modifiers + cell modifier − Σ active treatment coverage) is unchanged. Subtype overrides apply at the template-contribution step only.

### v1 usage

Three disorder templates ship subtype branches in v1.1:

- **PTSD (`ptsd_canonical_v1`)**: `hyperarousal`, `dissociative`. Exclusive. Selection by clinician (PCL-5 does not reliably differentiate; MDI or DES-II recommended).
- **MDD (`mdd_canonical_v1`)**: `melancholic`, `atypical`. Exclusive but optional — many MDD patients fit neither. Selection by clinician with optional algorithm-suggested label based on PHQ-9/MADRS item patterns.
- **OCD (`ocd_canonical_v1`)**: subtype branches reserved for v1.2; current symptom-dimension splitting (contamination / checking / symmetry / harm / hoarding) handled at the subsystem modifier level.

Other templates may add subtype branches in future revisions; the schema supports it without further changes.

### Audit and versioning

Each `SubtypeOverride` entry is versioned with the disorder template version. When a template revision updates a cell's override, patient profiles pinned to the previous template version retain the previous override values until re-baselined. Same versioning discipline as the rest of the schema.

## Extension C — Brain type anchor

**Why this exists.** The disorder templates `22`–`29` declare a `brain_type_anchor` field pointing at the primary brain type(s) the disorder most often resolves to. This convention is used by the type-suggestion engine to seed a type guess when the patient has a committed diagnosis but no questionnaire results yet, and by `20-brain-types.md` to surface the reverse mapping (which disorders typically resolve to each type). The field is referenced by templates but was not defined in the schema. Defining it here.

**Scope.** Add one optional field to `DisorderTemplate`. Mechanical schema change. Backward-compatible.

### Schema addition

```typescript
type DisorderTemplate = {
  // ... existing fields ...
  brain_type_anchor?: BrainTypeRef[];  // ordered by anchoring strength
};

type BrainTypeRef = {
  type_id: string;                    // matches BrainType.id from 20-brain-types.md
  strength: "primary" | "secondary";  // primary = strongest anchor; secondary = common overlap
  notes?: string;                     // optional clinical note on the anchoring
};
```

### v1 anchoring map

| Disorder template | Primary anchor | Secondary anchor |
|-------------------|----------------|------------------|
| `ocd_canonical_v1` | Type 4 (Compulsive-Locked) | — |
| `mdd_canonical_v1` | Type 2 (Anhedonic-Depleted) | Type 5 (Cognitive-Fogged) |
| `gad_canonical_v1` | Type 1 (Anxious-Vigilant) | Type 3 (Ruminative-Internal) |
| `panic_canonical_v1` | Type 1 (Anxious-Vigilant) | — |
| `sad_canonical_v1` | Type 1 (Anxious-Vigilant) | Type 2 (Anhedonic-Depleted) on reward-deficit dimension |
| `ptsd_canonical_v1` | Type 6 (Trauma-Imprinted) | Type 1 (Anxious-Vigilant) on hyperarousal subtype |
| `adhd_canonical_v1` | Type 5 (Cognitive-Fogged) | Type 2 (Anhedonic-Depleted) on motivation dimension |
| `insomnia_canonical_v1` | (no primary anchor) | Type 1 if hyperarousal-driven |
| `adjd_canonical_v1` | (no primary anchor) | depends on dominant symptom branch |

Adjustment Disorder and Insomnia intentionally lack a primary anchor — their presentations are heterogeneous and the brain type is better determined from the patient's actual cell vector rather than seeded by the diagnosis.

### Computation use

When the patient has a committed diagnosis but no questionnaire results yet (e.g., between intake and first questionnaire delivery), the platform may seed a tentative brain type suggestion from the primary anchor. As soon as questionnaire results arrive and the cell vector is computed, the closest-match algorithm in `20-brain-types.md` becomes authoritative. The provider commits the final type as before.

## Implementation notes

**Migration.** No data migration required for either extension. Existing disorder templates without subtype branches behave identically. Existing patient profiles without subtype assignments behave identically. The new fields are opt-in.

**Type generation.** Both extensions add optional fields to existing TypeScript types in the backend. Drizzle schema gets a JSONB field for subtype branches on the disorder template table and a JSONB field for subtype overrides on the cell table. PatientProfile gets a normalized `patient_disorder_subtype_assignments` table.

**Frontend impact.**

- Patient detail screen: subtype indicator chip below the disorder chip (e.g., "PTSD · Dissociative subtype"). Clickable to view the rationale.
- Treatment fit table: ranks computed using the subtype-overridden effective state. No UI change needed beyond the indicator chip.
- New-patient flow: subtype selection is deferred to first visit, not collected at intake.
- Sleep cells: render natively in the brain map once the new regions are added to the SVG anatomical layer. No structural change to the rendering pipeline.

**Validation.**

- Disorder template validation must check that every `subtype_overrides` entry's `subtype_id` matches a `subtype_branches` entry in the same template.
- Patient profile validation must check that every `disorder_subtype_assignment` references a valid template + subtype_id pair.
- Subtype overrides without `sources` should fail validation (overrides are clinically meaningful and must be evidence-backed).

## What this unlocks

**For insomnia:** native circadian-system cells; drug coverage profiles for DORAs and melatonin agonists become authorable; sleep cells across MDD, anxiety, and PTSD can be promoted from vegetative proxies.

**For PTSD:** clean encoding of the DSM-5 dissociative subtype; clinically realistic representation of subtype fluidity; no template duplication.

**For future:** any disorder with neurobiologically distinct subtypes (melancholic vs. atypical MDD, BD-I vs. BD-II once added, restricting vs. binge-purge anorexia in v2) uses the same mechanism. The pattern is reusable.
